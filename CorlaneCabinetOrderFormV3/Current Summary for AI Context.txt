📜 Session Summary: Mortise & Screw Hole Placement Refactor
🎯 Objective
Replace the fragmented mStartAdditional/mEndAdditional hacks in MortiseCalculator and MortiseScrewHoleCalculator with a clean, discrete placement model that allows uniform shifting of entire mortise/screw hole groups along an edge, while keeping screw holes perfectly synced.

🧱 Architecture Changes
New Spec Records (Rendering/V4/Core/JoineryPlacementSpecs.cs)

MortisePlacementSpec & ScrewHolePlacementSpec records
Replaced mStartAdditional/mEndAdditional with a single OffsetAlongEdge parameter
Maintains all existing parameters (Edge, EdgeLength, PartWidth, PartHeight, OffsetFromEdge, ForceTwoTenons, BlindStart/StopOverride, FullThicknessTenon, MaterialThickness34)
Placed in CorlaneCabinetOrderFormV3.Rendering.V4.Core for clean MVVM separation
New Calculator Methods

MortiseCalculator.ComputeMortisePocketsFromSpecs(MortisePlacementSpec, JoineryConfig)
MortiseScrewHoleCalculator.ComputeScrewHolesFromSpecs(ScrewHolePlacementSpec, JoineryConfig)
Existing methods remain untouched for backward compatibility
OffsetAlongEdge is applied uniformly to all computed ranges, eliminating asymmetric shifts
Call Site Mapping (PanelGeometryCalculator.cs)

Left Edge (Corner90 Deck): OffsetAlongEdge = RightBackWidth - (2*mt34) - ToeKickRightWidth
Top Edge (Corner90 Deck): OffsetAlongEdge = -mt34
Bottom Edge (End Panel w/ TK): OffsetAlongEdge = length - TKHeight
Screw holes use identical OffsetAlongEdge values to stay mathematically locked to their mortise groups
All replacements use the new ...FromSpecs methods; legacy calls remain intact
✅ Key Benefits
Single source of truth for positioning: OffsetAlongEdge shifts entire groups uniformly
Zero desync risk: Screw holes consume identical offset values
MVVM-aligned: Pure data records, pure math calculators, no UI/state coupling
Incrementally safe: Original methods preserved; call sites can be migrated at your pace
Fully testable: Specs are immutable records; calculators are deterministic functions
