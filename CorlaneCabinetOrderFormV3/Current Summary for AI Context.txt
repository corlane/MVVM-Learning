Session Summary: Corlane Cabinet Order Form – DXF Export Pipeline & 90° Corner Cabinet Joinery
🎯 Session Overview
Successfully implemented sequential tenon placement for Base 90° corner cabinet Tops, Decks, and Shelves (L-shaped panels). Refactored the outline generation strategy from fragile index-based insertion to a robust, sequential edge-chaining approach. Resolved compilation errors related to Vector2 equality checks. Documented next-phase requirements for mortises, screw holes, and asymmetric shelf hole drilling on 90° corner cabinets.

🐛 Problem Identified
The initial attempt to add tenons to L-shaped panels used index-based vertex insertion into a pre-built List<Vector2>. This approach:

Broke clockwise winding order when multiple tenons were inserted
Caused index-shifting bugs that corrupted subsequent edge coordinates
Produced "spaghetti" DXF output with crossing lines and invalid polylines
Failed to respect the constraint that the two edges intersecting the inner radius corner must remain joinery-free
✅ Solution Implemented
Replaced index manipulation with a sequential, edge-by-edge outline builder. The new flow constructs the L-shape clockwise, chaining vertices naturally so the end of one edge becomes the start of the next.

🔹 Core Changes in PanelGeometryCalculator.cs
ComputeLShapeJoinery Method

Clears the seed point and rebuilds the outline sequentially
Draws the inner radius arc first (no joinery)
Chains 4 outer edges using dedicated builders:
AppendHorizontalEdgeWithTenons (Top & Bottom edges)
AppendVerticalEdgeWithTenons (Right & Left edges)
Explicitly skips joinery on the 2 edges touching the inner radius corner
Maintains strict clockwise winding order
Edge Builder Helpers

Compute edge length and direction (left→right or top→bottom)
Call TenonCalculator.ComputeTenonRanges for proper spacing
Project tenons outward using dadoDepth and directional flags (protrudePositiveY/protrudePositiveX)
Append vertices sequentially: straight segment → tenon start → protrude → across → return → next segment
Record global thinning pocket coordinates for each edge
Handle zero-tenon edges gracefully by drawing a single straight line

📐 Architectural Decisions
Sequential Chaining > Index Insertion: Eliminates winding order corruption and index-shifting bugs. DXF polylines are now mathematically guaranteed to be valid.
Direction-Aware Protrusion: Tenons always face outward from the L-shape boundary, regardless of edge traversal direction.
Inner Corner Protection: The two edges adjacent to the radius are explicitly excluded from joinery calculation, preserving structural integrity and CNC toolpath safety.
Modular Helpers: AppendHorizontalEdgeWithTenons and AppendVerticalEdgeWithTenons isolate axis-specific logic, making future adjustments (e.g., custom blind starts, asymmetric tenons) trivial.

🔍 Context Notes for Future Sessions
The DXF pipeline expects clockwise winding order for valid polylines
TenonCalculator.ComputeTenonRanges remains the single source of truth for tenon spacing
Thinning pockets are recorded as (x1, x2, y1, y2) tuples and passed to DxfWriter
Vector2 is a lightweight readonly struct without equality operators; always compare .X and .Y directly
L-shape geometry uses insetLf, insetRf, insetLd, insetRd derived from cabinet dimensions minus material thickness and gaps
