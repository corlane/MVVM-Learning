📋 DXF Export Pipeline Refactoring (V4) – Complete Session Summary

🎯 Objective
Refactor the legacy DxfExporter into a modular, unit-testable V4 pipeline that decouples geometry calculations from netDxf until the final rendering step, while preserving WYSIWYG accuracy with the 3D rendering pipeline. Recent updates include precise mortise centering with oversize expansion, independent screw hole placement in joinery gaps, and full adapter pipeline stabilization.

🏗️ Final Architecture: Rendering.V4

Core Models (CorlaneCabinetOrderFormV3.Rendering.V4.Core)

File	Purpose
Vector2struct.cs	Lightweight Vector2 struct for 2D coordinates (decoupled from netDxf)
PartBounds.cs	PartBounds record, Edge flag enum, MortiseEdge flag enum, ScrewHoleEdge flag enum, PartInfo record, JoineryConfig record
PartGeometry.cs	Immutable DTO holding final computed geometry: outline vertices, tenon thinning pockets, mortise pockets, screw holes
PartInfo Record:

internal record PartInfo(
    string Name,
    PartBounds Bounds,
    string Material,
    int Quantity,
    Edge TenonEdges,
    MortiseEdge MortiseEdges,
    ScrewHoleEdge ScrewHoleEdges, // 👈 Added for independent screw hole control
    string? EdgeBand,
    string? Notes,
    double TkHeight = 0,
    double TkDepth = 0);
JoineryConfig Record:

internal record JoineryConfig(
    double BlindStart, BlindStop, DadoDepth, MortiseDepthClearance,
    TenonThickness, TenonClearance, TenonPocketOversize, MortiseOversize,
    GapWidth, GapSpacing, ScrewPilotHoleDiameter, Thickness34,
    double TenonThinningOverrun = 0.375);
Adapters (CorlaneCabinetOrderFormV3.Rendering.V4.Adapters)

File	Purpose
CabinetInputAdapter.cs	Maps legacy PartListEntry → V4 PartInfo, resolves edge flags, enriches end panels with TkHeight/TkDepth, maps LockDadoSettings → JoineryConfig
Key Methods:

MapParts(IEnumerable<PartListEntry>, LockDadoSettings?, double tkHeight, double tkDepth)
MapSettings(LockDadoSettings?)
ResolveEdgeFlags(string partName) → Edge
ResolveMortiseEdges(string partName) → MortiseEdge
Note: ScrewHoleEdges currently defaults to casted MortiseEdges for parity, but can be resolved independently later.
Calculators (CorlaneCabinetOrderFormV3.Rendering.V4.Calculators)

File	Purpose
TenonCalculator.cs	Pure math: computes tenon ranges, gap spacing, thinning pocket rectangles
PanelGeometryCalculator.cs	Assembles final PartGeometry: outlines (standard + toekick), tenon protrusions, thinning pockets, mortise pockets, screw holes, mirroring for Right End panels
MortiseCalculator.cs	Computes mortise pocket rectangles using TenonCalculator.ComputeTenonRanges() + symmetric oversize expansion (ignores blind clamping to allow full expansion)
MortiseScrewHoleCalculator.cs	Computes through-holes centered in gaps between tenons/mortises, offset from edge by Thickness34 / 2
PartGeometryExtensions.cs	MirrorAcrossVerticalCenterline() extension method for PartGeometry
Key Logic in PanelGeometryCalculator.Compute():

Detects end panels with toekicks → uses BuildEndPanelWithToeKick()
Otherwise builds standard outline with tenon protrusions on flagged edges
Computes tenon thinning pockets alongside outline
Computes mortise pockets on flagged edges (centered on tenons, expanded by MortiseOversize)
Computes screw holes in gaps on flagged ScrewHoleEdge sides
Mirrors entire PartGeometry across vertical centerline for "Right End" parts
Returns PartGeometry DTO
DXF Layer (CorlaneCabinetOrderFormV3.Rendering.V4.DXF)

File	Purpose
DxfLayerManager.cs	Defines CNC layers with ACI colors: PartOutline, TenonThinningPocket, MortisePocket, DrillHolesBlind, DrillHolesThrough
DxfWriter.cs	Converts List<PartGeometry> → DxfDocument: outlines → Polyline2D, pockets → rectangles, holes → circles, assigns layers
Orchestrator (CorlaneCabinetOrderFormV3.Rendering.V4.Orchestrator)

File	Purpose
DxfExportPipeline.cs	Wires Adapters → Calculators → Writer: accepts PartListEntry + settings + toekick dims, validates, generates DXF, exports to file
🔧 Key Implementation Details

netDxf Version Compatibility: Uses DxfDocument, Polyline2D, Vector2/Vector3, doc.Entities.Add(), doc.Layers.Add(). Layer colors use AciColor. Aliases netDxfVector2/netDxfVector3 to avoid collision.
Coordinate System: (0,0) is bottom-left. X maps to part width, Y maps to part height.
Toekick Notch Geometry: BuildEndPanelWithToeKick(depth, height, tkHeight, tkDepth) generates the stepped outline for end panels.
Mirroring Logic: Applied to "Right End" panels only. Mirrors across vertical centerline: X' = Bounds.Width - X, Y unchanged. Mirrors outline, thinning pockets, mortise pockets, and holes.
Mortise Calculation: Reuses TenonCalculator.ComputeTenonRanges() for positioning. Applies MortiseOversize symmetrically outward from tenon boundaries. No longer clamped to blindStart/blindStop, allowing full expansion past limits.
Screw Hole Calculation: Places through-holes at the midpoint of each gap between tenons. Offset from the joinery edge by Thickness34 / 2. Controlled by ScrewHoleEdge flags.
📦 Export Command Integration (POBatchListViewModel.ExportDxf())

foreach (var cabinet in _cabinetService.Cabinets)
{
    string label = PartsListBuilder.FormatLabel(cabinet, index++);
    var parts = PartsListBuilder.BuildForCabinet(cabinet, label);
    
    double tkHeight = 0, tkDepth = 0;
    if (cabinet is BaseCabinetModel baseCab)
    {
        var dim = BaseCabinetDimensions.From(baseCab);
        tkHeight = dim.TKHeight;
        tkDepth = dim.TKDepth;
    }

    foreach (var part in parts)
    {
        var pipeline = new DxfExportPipeline(new[] { part }, joinerySettings, tkHeight, tkDepth);
        if (!pipeline.ValidateInput()) continue;
        
        string safeName = SanitizeFileName($"{part.CabinetLabel} — {part.PartName}");
        pipeline.ExportToFile(Path.Combine(dlg.FolderName, safeName + ".dxf"));
    }
}

🧠 Key Architectural Decisions

Decoupling: Geometry math isolated in Calculators layer; netDxf only touched in DXF layer
Immutability: PartInfo and PartGeometry are records for thread-safety
Flag Enums: Edge, MortiseEdge, and ScrewHoleEdge control joinery/placement per part independently
Post-Calculation Mirroring: Right End panels mirrored after all geometry computed
Tuple-Based Geometry: Pockets/holes use (double, double, double, double) or (double, double, double) tuples for simplicity
Cabinet Context Injection: Toekick dimensions passed through pipeline constructor, not stored in parts
